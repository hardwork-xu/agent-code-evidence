# 持久模块摘要与选择性图回放

本实验 API 保持 ContextProof 有界静态解析器的输出。复用 unknown 图后仍然是
unknown；它不认证一般 Python 行为，也不证明上下文对 Agent 有用。

## 状态与执行流程

`GraphSession` 持有固定锚点和图限额、源码哈希、上一版本图、每张图咨询过的
文件集合，以及仅保留当前版本的模块摘要缓存。`ModuleCache` 的键是
`(source path, SHA256(source))`。摘要包含 AST、已守卫绑定、声明和通配导入状态，
也保存解析失败。绑定字典和列表经过冻结；AST 为内部只读使用，并非 Python
层面深度不可变。返回图及 `index_stats` 都不暴露缓存对象。

```mermaid
flowchart LR
    S[不可变源码映射] --> H[哈希全部源码并比较目录]
    H --> T[在新事务中清理摘要]
    T --> V[验证旧图读取集合]
    V -->|未改变| C[复制并重新封装旧输出]
    V -->|失效| I[索引改变的模块]
    I --> G[用当前目录重建图]
    C --> P[全部锚点成功后发布]
    G --> P
```

更新首先复制输入映射，校验路径和文本。新缓存事务仅保留与当前哈希一致的
摘要。只要有图需要重建，就重新建立当前模块目录；源文件摘要从不保存跨文件
导入解析结果。未变摘要跳过解析、绑定索引和源文件内部守卫。跨文件解析仍查询
当前候选目录，并记录所有咨询路径，包括子模块回退前未找到属性的包文件。
从已缓存摘要构建新图时，这些读取也必须重新登记。

复用时复制旧图，更新快照出处并重新封装。目录增删会保守地使选择性复用失效；
目录相同时，任何已咨询源码改变都会触发重建。严格默认模式还要求图没有 frontier；
实验性选择模式则保留已有 frontier。所有锚点成功后，才发布新摘要、图和读取集合。
更新失败不会破坏上一成功会话。即使所有图都命中缓存，也会清理未读文件的旧摘要。

## 公平对照

| 模式 | 索引方式 | 图复用条件 |
|---|---|---|
| `warm_ast_rebuild` | 缓存 AST，每版本重建绑定 | 不复用 |
| `whole_corpus_guard` | 同上 | 全部源文件内容相同 |
| `read_set_any_status` | 同上 | 已咨询文件与目录相同 |
| `incremental_index_rebuild` | 持久已守卫模块摘要 | 不复用 |
| `incremental_whole_corpus_guard` | 同样的模块摘要 | 全部源文件内容相同 |
| `incremental_read_set` | 同样的模块摘要 | 已咨询文件与目录相同 |

所有方法在每版本的多个锚点之间共享一次索引结果。组合了整库检查与增量索引的
方法是留出实验的主要基线，因为它在源码相同的版本也能免去图重建。原有
`read_set_certificate` 仍是公共默认值，保留完整性门槛。

## 开销与正确性边界

每次更新都哈希全部输入源码、检查完整路径集合，不声称源码读入是次线性的。
需要重建图时，目录构造访问全部当前模块；只有变化模块需要重新解析、建立绑定
和执行守卫。读取集检查开销取决于记录的咨询次数，图复制和重建受输出限额约束。
实验计时包含归档解码和校验，因此省去索引并不能消除这些成本。缓存存储随当前
摘要和图输出增长，不随历史版本数增长；更新过程中可能同时保留旧状态与候选状态。
RSS 包含解释器与输入源码，不是单独的缓存占用。

条件正确性论证遵循已有依赖追踪思想：若确定性解析器咨询的全部输入、策略与
目录不变，其规范结果除快照身份外应相同。“全部咨询已正确登记”是前提，不是
对任意 Python 程序的定理。动态分派、生成代码和不支持的绑定仍有明确限制。
同一解析器的全新重建只是回放参照，不是独立语义判定器。

## 源码导读与验证

1. `src/contextproof/reuse.py`：`GraphSession.update`、失效判断、防御性复制和
   原子状态发布。
2. `src/contextproof/module_cache.py`：摘要容器、当前版本清理和工作量计数。
3. `src/contextproof/dependencies.py`：`_Corpus.from_texts` 与读取登记。
4. `src/contextproof/static_scope.py`：源文件内部歧义守卫。
5. `tests/test_incremental_module_cache.py`：摘要命中后的负依赖、通配状态、路径
   冲突、解析失败、截断、回滚、输出隔离，以及二十次编辑后的旧 AST 回收。
6. `scripts/run_incremental_holdout.py`：每版本无跨版本缓存参照、配对计时、独立
   RSS/tracemalloc 子进程及完整结果网格校验。

计数器位于图产物之外，仅报告上次成功更新的实际索引工作量。所有图命中时，
索引计数为零，但仍可能保留摘要。计数用于检查机制行为；性能结论应引用实验原始数据。

缓存只在进程内有效，不保证线程安全，也不接收外部序列化证书。调用者须提供
一致快照；从实时目录读取的混合时刻内容不能保证仓库原子语义。
